# AI Vulnerability Tester

This script uses an AI model (like OpenAI's GPT-4o mini) to attempt to validate vulnerabilities found in a scan report.

## Setup

1.  **Install Dependencies:**
    ```bash
    pip install -r requirements.txt
    ```

2.  **Set OpenAI API Key:**
    You *must* set your OpenAI API key as an environment variable:
    ```bash
    export OPENAI_API_KEY='your-api-key-here'
    ```

## Scan Report Format

The script expects a JSON scan report file structured according to `structs.py`. See the example below:

```json
{
  "scan_metadata": {
    "scan_id": "example-scan-001",
    "timestamp": "2024-07-28T12:00:00Z",
    "source_details": "ExampleWebApp v1.0 - /path/to/source or git@repo:user/project.git"
  },
  "vulnerabilities": [
    {
      "id": "vuln-001",
      "cwe_id": "CWE-89",
      "description": "Potential SQL Injection in user search.",
      "file_path": "app/routes/users.py",
      "line_number": 55,
      "endpoint": "/api/users/search",
      "method": "GET",
      "parameters": ["query"],
      "potential_exploit_type": "SQLi",
      "target_url_base": "http://127.0.0.1:5000" 
    },
    {
      "id": "vuln-002",
      "cwe_id": "CWE-79",
      "description": "Potential XSS in profile update.",
      "file_path": "app/routes/profile.py",
      "line_number": 112,
      "endpoint": "/profile/update",
      "method": "POST",
      "parameters": ["bio"],
      "potential_exploit_type": "XSS",
      "target_url_base": "http://127.0.0.1:5000"
    },
    {
      "id": "vuln-003",
      "description": "Missing authorization check on admin endpoint.",
      "endpoint": "/admin/dashboard",
      "method": "GET",
      "potential_exploit_type": "Auth Bypass",
      "target_url_base": "http://127.0.0.1:5000"
    }
  ]
}
```

**Important:** Ensure the `target_url_base` in each vulnerability points to the *running* web application you want to test against.

## Usage

Run the script, providing the path to your JSON scan report:

```bash
python ai_tester.py path/to/your/scan_report.json
```

**Options:**

*   `-l N`, `--limit N`: Set the maximum number of AI queries to attempt per vulnerability (default: 5). A query typically involves asking for a command, assessing the result, or asking for a suggestion.
*   `-o FILE`, `--output FILE`: Save the detailed JSON results of the tests to the specified file.

Example with options:

```bash
python ai_tester.py reports/latest_scan.json -l 3 -o test_results.json
```

## How it Works

1.  Parses the input scan report.
2.  For each vulnerability:
    *   Asks the AI to generate a test command (e.g., `curl`).
    *   Executes the command against the `target_url_base` + `endpoint`.
    *   Sends the command's output (stdout, stderr, status code) back to the AI.
    *   Asks the AI to assess if the test was successful based on the output.
    *   If successful, marks it and moves on.
    *   If failed, asks the AI for a modification or a new approach.
    *   Repeats this process up to the query limit.
3.  Prints a summary and optionally saves detailed results.

## Security Considerations

*   **Command Execution:** The script executes commands generated by the AI using `subprocess.run(..., shell=True)`. While convenient, `shell=True` can be risky if the AI generates malicious commands. Review the AI-generated commands logged by the script, especially in sensitive environments.
*   **API Key:** Protect your OpenAI API key. Do not commit it directly into code.
*   **Target Application:** Only run this script against applications you have explicit permission to test.
